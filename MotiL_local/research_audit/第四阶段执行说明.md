# 第四阶段：固定协议的验证集性能实验

启动日期：2026-10-09。本文记录执行方案，**不是实验结果报告**。队列现已全部完成；最终结果见 `研究第四阶段结果.md` 与 `phase4_validation_results.json`。启动前的完整计划保存在 `phase4_manifest.json`。

## 已固定的实验

1. B0、B1、B2b 各进行 200 minibatch 的继续预训练，batch size=16、固定 4096 个 ZINC 分子，配对 seeds=2024/2025/2026，共九组。
2. 作者原编码器对照和三种继续预训练编码器，各进行上述三个 seed 的 ESOL 微调，共十二组；全部采用公开 ESOL 100 轮、batch size=64、init LR=1e-3、final LR=1e-6、wd=1e-5、warmup=0。
3. scaffold_balanced split seed 固定为 2024；各组对应的预测头初始化 seed 与继续训练 seed 配对。保存 train/val/test SMILES 文件并比较内容哈希。
4. 只按验证 RMSE 选最佳 checkpoint，并重新载入检查验证 RMSE 一致性。固定预算结束时才汇总三 seeds 的均值、样本标准差及配对差值。

作者对照不接受继续预训练。所有继续预训练组共享作者编码器起点，但投影 FFN、DDPM MLP 和两个 Adam 状态重新初始化；这不是作者完整训练状态恢复，也不是三次独立从头预训练。

继续预训练仍保持公开 atom-feature DDPM 行为，不声称实现论文的邻接扩散公式。当前 B2b 仍是全实例参与类型平均，尚未引入 I1 实例级目标或 I2 边界学习。

## 测试集处理

`downstream_validation_only.py` 除了关闭逐轮测试，还截断最终测试与测试 ensemble 评价，直接返回验证检查点结果。预测入口设有拦截：凡预测数据包含当前 test split 的 SMILES 即报错停止。

新增的 CPU 一轮安全检查已经通过：训练评价、验证评价、重载后验证评价共三次允许预测，测试预测次数为零。安全检查不计入性能比较。

本轮不产生测试分数。此前该 ESOL 测试集已经在研究迭代中查看过，因此后续仍需新的划分或任务来支持更强泛化结论。

## 配对比较预先定义

| 比较 | 回答的问题 |
| --- | --- |
| 作者权重 → B0 | 当前同起点继续训练本身的作用 |
| B0 → B1 | 统一基序深度的作用 |
| B1 → B2b | 完整实例保留及取消类型截断的综合作用 |

不根据中途损失或验证结果调整参数，不从这些组中选一个“最好种子”。本次预先执行全部十二个验证模型；B2a-1/B2a-2 的扩展实验不由队列自动启动。

## 输出及失败规则

- `phase4_runs_20261009/manifest.json`：启动前的全量计划、源码/数据/权重哈希与完整命令。
- `progress.json`：当前步骤及完成情况。
- 各继续预训练目录：逐步损失、梯度、实际参数差、更新和跳过次数、耗时、显存以及模型/优化器状态。
- 各 ESOL validation JSON：验证最优 epoch、验证值、重载检查、测试拦截计数和保存检查点。
- 成功全部结束后：`complete.json` 与 `research_audit/phase4_validation_results.json`，只含验证结果。

任一子过程失败、非有限值、配对哈希不一致或测试预测触发时，队列停止并保存失败状态；不会自动调参、覆盖或重启。模型与训练数据不加入 Git。
