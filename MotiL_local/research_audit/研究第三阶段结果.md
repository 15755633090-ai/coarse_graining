# 第三阶段：完整更新与下游接线

日期：2026-10-09。完成真实 ZINC 类型上限验证、完整 DDPM/分子/基序参数更新、短程配对检查及下游 ESOL 入口。**本阶段确实更新了模型参数**，不再只是推理或梯度存在性检查。

## 1. 数据与真实十类上限

对 ZINC 250,000 条 SMILES 做 RDKit canonical isomeric-SMILES 去重，得到 250,000 个有效唯一分子。与 ESOL/BBBP/ClinTox/BACE 全部已知分子做完全相同 canonical 字符串排除，去掉 1 个；排序后以 NumPy default_rng(2024) 固定选择 4,096 个。

子集与上述四个数据集的该种精确重叠为 0。此步骤不证明作者权重原始预训练无重叠，也不排除骨架近似、互变异构体等其它关系。

子集 SHA256：`e52dceb4ea509aeae24d50cd68c687becb29ba32c6b48b2438856d2c6cacb999`。

按文件顺序每 16 个分子分批，共 256 批，其中 **20 批（7.8125%）超过十类**。第一批存在十一类、65 个实例；B2a-2 只保留十类、64 个实例，B2b 保留十一类、65 个实例。

使用作者权重实际前向，得到 B2a-2 `[10,300]` 与 B2b `[11,300]`，均为有限值。该示例额外保留的类型是 Hydroxyl。证据：`real_type_cap_verification.json`；完整数据准备记录为 `phase3_data_manifest.json`。

## 2. 完整训练入口

`continue_motif_pretraining.py` 从官方快照提取 MLP/DDPM 实现，仅移除失配的额外 False 参数。仍保留公开原子特征 DDPM 的数学行为，包括此前指出的输入与系数问题；**不能把它称为论文邻接扩散的正确实现**。

同一批次先执行扩散 Adam 更新，然后交替执行分子或基序 PointwiseLoss 更新。分子和基序表示经过原预训练 FFN，再进入损失，保持公开调用链。五组共用之前的 clone 兼容修复与低类型批次跳过规则。

起点为作者 CMPNN 编码器权重，**预训练投影 FFN、DDPM MLP 和两个 Adam 优化器状态均重新初始化**。因此是匹配起点的探索性继续预训练，不是恢复作者完整训练状态。

每个更新检查：有限损失、有限梯度、有限更新后参数，共享编码器梯度范数及参数差范数均大于 0；每次写入日志。保存编码器、完整模型/MLP/优化器状态及初末哈希。当前入口没有提供完整断点恢复功能。

批次顺序使用独立 NumPy generator；扩散、分子视图和基序视图分别按 minibatch 重置 RNG。不同实例数导致 dropout 消耗量不同，不能保证每个实例的 dropout mask 一一相同，但不会把这种消耗差异带入下一阶段的扩散 RNG。

## 3. 已执行的有界更新检查

先对 **五组各运行两个 minibatch**，覆盖两次扩散、一次分子、一次基序更新。全部完成，未跳过基序更新。

再对 **B0/B1/B2b 各运行 20 个 minibatch，seed=2024**。每组实际执行 20 次扩散、10 次分子、10 次基序更新，跳过 0 次；损失、梯度和更新后参数全部有限。

检查确认：各组初始编码器、投影 FFN、DDPM MLP 的张量哈希，以及批次序列哈希完全一致；结束时编码器哈希不同。没有根据损失改变学习率、步数或选择训练中间状态。

## 4. 下游接线完成

将未继续训练的作者权重，以及上述三个 20-step 编码器，接入相同 ESOL 微调入口。

- 全部严格加载完整 CMPNN 编码器权重。
- 四组采用相同初始化 seed=2024、相同 scaffold_balanced split seed=2024。
- 保存的 train/validation/test SMILES 文件 SHA256 四组完全一致。
- 每组只运行 **一轮**，完成性质损失更新、验证集选定检查点、保存重载以及最后评价。
- 独立 AST 入口关闭原来每轮的测试预测与打分；最终测试仍位于验证选择之后。

首次下游接线因 AST 检查与实际调用结构不一致，在训练开始前失败。修正为只处理 epoch 循环中的 predict/evaluate_predictions；失败目录保留，成功证据存入独立 `downstream_wiring_v2/`，没有覆盖失败记录。

一轮下游验证只证明路径接通。原公开 ESOL 配置为 100 轮，此处的一轮**不是相同性能评估协议**；保存的数值不能用于给方法排序、调整设计或宣称改进。证据：`phase3_downstream_verification.json`。

## 5. 当前可下的结论与下一决策点

已证明：超过十类的真实批次确实存在；全部分支能实际更新共享编码器；不同基序处理经过短程更新形成了不同权重；新权重可被标准下游性质模型严格加载并训练。

尚未证明：任一修正提高性质预测指标；实例级目标有效；边界/连接端点已经被学习。B2b 仍按类型平均全部实例，I1/I2 尚未实现。

下一步才是按完整公开下游训练轮数进行预先固定的探索性比较，并保留作者权重不继续训练的对照。当前 **200 minibatch × 三 seeds** 的扩展协议未运行，不能与这次 20-step 稳定性检查混同。

## 6. 文件与运行边界

- `prepare_phase3_data.py`：固定子集与真实批次审计，不做参数更新。
- `verify_real_type_cap.py`：真实批次前向，不做参数更新。
- `continue_motif_pretraining.py`：实际参数更新，必须显式给定 2–200 的 steps 和新输出目录。
- `run_phase3_checks.py`：五组 2-step＋三组 20-step；失败即停止，不改参重试。
- `downstream_phase3_entry.py`：下游入口，禁止逐轮测试评价。
- `verify_phase3_downstream.py`：四组一轮 ESOL 接线验证，会实际更新下游参数。
